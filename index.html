ChatGPT Skills: What They Are and Who Can Actually Use Them

ChatGPT skills are closer to a folder than to a feature: instructions, examples and scripts the assistant picks up on its own when a task calls for them.

A skill is a folder, not a feature

The help centre defines one as a reusable, shareable workflow that helps the assistant complete a specific task more consistently, made up of instructions, examples and code, plus reusable steps and scripts for more structured work. Simon Willison, writing in December 2025, described the underlying shape more bluntly: a folder with a markdown file and some optional resources and scripts, which is why the format spread across tools so quickly. He also documented a skills directory living inside the Code Interpreter environment, reachable by asking the assistant to zip it up. Once installed, skills are not invoked by name; the assistant picks up one or more of them when they look helpful.

Where they live in the interface

Select Plugins in the sidebar, then open the Skills tab inside the Plugin Directory. That page splits into Installed, Created by me, Shared with me, and Shared by your workspace, which is a useful division once a team has more than a handful. Eligible accounts start with one already present: skill-creator. It is not decorative. When you ask the assistant to build or change a skill, it uses skill-creator to generate, update or troubleshoot the result, so the authoring path and the running path are the same mechanism. Worth knowing that plugins and skills are related but distinct, since a plugin can contain skills, apps, or both. Skills carry reusable instructions; apps connect to external services, and that is the cleanest way to remember which tab you actually want.

Four routes to getting one

Route one is conversational: open Skills, choose Create, then Create with chat, or simply ask for a skill mid-conversation and answer the follow-up questions before installing it. The second is the editor at chatgpt.com/skills/editor, reached through Create and then Create with editor, which suits anything you intend to maintain. The third is installing something already shared with you or your workspace, from the Shared with me or Shared by workspace tabs via the more options menu. The fourth is uploading a folder from your computer. Sharing works the same way in reverse, with a searchable list of people and groups, a copyable link, and access permissions you set per skill.

Uploads are scanned, and some are blocked

Anything uploaded goes through an automated scan before it becomes available. Most skills are usable as soon as that finishes. Some are marked Needs Review, which means you have to read additional information before using them. Skills that appear to contain risky content or behaviour are marked Blocked and cannot be used at all. The documentation attaches an important qualifier: the scan should not replace your own review, policies or judgement. Given that a skill can carry instructions, supporting files and executable code, treat one downloaded from an external source or another organisation exactly as you would treat a pull request from a stranger, and read it before installing. The Blocked category is reassuring precisely because it exists, but anything that passes a scan has only passed a scan.

Eligibility, and where admins draw lines

Availability covers eligible ChatGPT Business, Enterprise, Healthcare and Edu users, subject to workspace settings and product availability, and the same mechanism is supported in Codex and other OpenAI products with installation and syncing differing by surface. For Enterprise and Edu workspaces, administrators review which roles may create, use, share or install skills, and workspace defaults follow the current product configuration. The practical consequence for anyone planning a rollout is that the interesting conversation is with your administrator rather than with the product. Build the skill, then find out who in your organisation is permitted to install it, in that order or you will build something nobody can run. Administrators also decide whether sharing is permitted at all, which determines whether a skill can spread past the account that created it.

Worth knowing before you build one

skill-creator is already there

Eligible accounts include it by default, and asking the assistant to create or fix a skill invokes it automatically. Authoring a skill is itself a skill, which is a tidier arrangement than it sounds.

Once installed, the assistant chooses one or more skills when they appear helpful for the task at hand. You are shaping default behaviour rather than adding a command you have to remember.

Building your first one

  1. Check eligibility
    Confirm your account type is covered and that workspace settings permit skills. In Enterprise and Edu workspaces an administrator decides which roles may create, use, share or install them.
  2. Describe it in chat
    Open Skills, choose Create, then Create with chat, or ask for one mid-conversation. The assistant asks follow-up questions and prompts you to install the result when it is ready.
  3. Move it to the editor
    For anything you plan to maintain, rebuild or refine it at chatgpt.com/skills/editor. A skill that lives only in a chat transcript is hard to revise six weeks later.
  4. Share with permissions set
    Use the more options menu to share, search for the people or groups who need it, and set access so only the intended audience can install it in your workspace.

Questions people ask first

Who can use chatgpt skills?

The help centre describes them as available to eligible ChatGPT Business, Enterprise, Healthcare and Edu users, subject to workspace settings and product availability. They are also supported in Codex and other OpenAI products, though installation and syncing differ by product and surface.

Do I have to invoke a skill by name?

No. After a skill is created and installed, the assistant can automatically use one or more of them when they are helpful for the task. That is the main difference from keeping a library of prompt templates you have to remember to paste.

What is the difference between a skill and a plugin?

A plugin can include skills, apps, or both. Skills provide reusable instructions and scripts, while apps connect to external services. In the interface, skills sit on their own tab inside the Plugin Directory rather than being a separate area entirely.

Is it safe to install chatgpt skills shared by another organisation?

Treat it as code review. Uploaded skills can contain instructions, supporting files and executable code, and while each upload is scanned and may be marked Needs Review or Blocked, the documentation says explicitly that the scan does not replace your own review and policies.

Can I edit a skill after creating it?

Yes. The Skills editor exists for exactly that, and asking the assistant to modify a skill invokes skill-creator, which generates, updates or troubleshoots it. Anything you expect to maintain is better built in the editor than left in a conversation.
